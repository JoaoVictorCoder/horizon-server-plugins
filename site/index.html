Everything a plugin author expects

If you have written a Bukkit or Paper plugin, you already know the shape. The difference is that it compiles to a native library and doesn't need a JVM.

Events

Join, quit, move, chat, clicks, block break and place, attacks, mob spawns, explosions, pistons, chest menus, ticks. Priorities and cancelling included.

Commands

Declared in plugin.yml or in code, with aliases, permissions and tab completion. Even //set-style names.

Permissions

permissions.yml with groups, inheritance, -permission to deny and homes.* wildcards.

Hot reload

/plugins reload reloads plugins and their configs while the server keeps running.

Scheduler

run_task, run_later, run_timer, and run_async, whose thread calls the server too (answered at the next tick) and has a handle back to the server thread.

Stable ABI

Plugins talk to the server through a C ABI. A plugin built with any Rust version loads in any server with the same ABI version.

Why run it

What you get from a Rust server with Rust plugins, compared with a typical Paper setup.

No JVM to tune

The server is one native binary built from Rust. There is no Java to install, no garbage collector, and no list of JVM flags to tune for memory and pauses.

Safer plugins

The Rust compiler catches null access, use after free and data races before a plugin ships. If a callback still panics, the panic is caught and logged, and the server keeps running.

The usual extras, built in

Permission groups and reloading plugins at runtime come with it. On Paper, each of those is a separate plugin.

An API you already know

on_enable, listeners with priorities, plugin.yml, config.yml, &a colours. A Paper plugin ports almost line for line.

Open and small

MIT licensed. The whole server side (API, plugin host and engine patch) is one repository you can read in an afternoon.

14.7 ms against 16.2 ms with 25 bots. Both hold 20 TPS, far below the 50 ms limit.

Get started

You need Rust, curl, tar, git and a C compiler. The first build takes about 10 minutes.

Build the server

Downloads Horizon at a pinned commit, applies the patch and builds only the server.

git clone https://github.com/JoaoVictorCoder/horizon-server-plugins
cd horizon-server-plugins
./build.sh

Add the game files

Prepared from your own copy of Minecraft. The easy way is to install the Horizon launcher and play once.

# the examples, plus any plugin you built
cp dist/plugins/* server/plugins/
cd server
./iniciar.sh --initSettings

Start it

Accept Mojang's EULA in eula.txt, then start. The terminal is the console.

./iniciar.sh
# then: op YourName, plugins, stop

To write your own plugin, add horizon-plugin-api as a git dependency with crate-type = ["cdylib"], then run cargo build --release and drop the library into plugins/. HorizonEdit is a whole plugin set up that way.
